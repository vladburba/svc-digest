# svc-digest

Автономный новостной дайджест. Собирает RSS, ИИ отбирает статьи под интересы из
`interests.md`, дважды в сутки шлёт дайджест в Telegram — утром и вечером.

Работает на боевом сервере `vlad-main` 24/7 с 2026-07-26.

## Как устроен

Три развязанные работы, общаются через базу (producer/consumer):

- **СБОРЩИК** (`collect`) — раз в час весь день: тянет RSS, отсеивает уже
  виденное, складывает новое в базу со статусом `new`. ИИ не зовёт — заход
  ничего не стоит. В чат молчит, шумит только в лог.
- **ФИЛЬТР** (`filter`) — в 08:00 и 20:00: отдаёт всё накопленное ИИ **одним
  пакетом**, раскладывает на `pending` (в дайджест) и `rejected`. Единственная
  работа, которая тратит квоту OpenRouter.
- **ОТПРАВИТЕЛЬ** (`send`) — в 08:30 и 20:30: забирает накопленное `pending`,
  рендерит, отправляет, помечает `sent`.

Смысл развязки: к 08:30 дайджест уже лежит готовым в базе — отправка не зависит
от того, живы ли в этот момент RSS и ИИ. Сборщик ретраится сам собой: лёг
источник сейчас — подберёт через час.

**Почему отбор вынесен в отдельную работу.** Дневная квота OpenRouter — 50
запросов **на аккаунт**, и она общая с проектом `vladburba-bot`. Пока ИИ жил
внутри сборщика, отбор запускался каждый час и съедал 7–16 запросов в сутки, по
большей части впустую — модель звали ради одной-двух статей. Пакетный отбор
дважды в сутки сводит расход к 2 запросам (максимум 6, если не ответит ни одна
модель цепочки) и заодно улучшает выбор: модель сравнивает статьи между собой,
а не судит каждую в одиночку.

Полная карта конвейера с диаграммой — в [`СХЕМА.md`](СХЕМА.md).

## Запуск локально (мак)

```bash
cd ~/проекты/svc-digest
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # вписать реальные значения
python digest.py collect      # сбор — бесплатно, ИИ не трогает
python digest.py filter       # отбор — ТРАТИТ общую квоту OpenRouter
python digest.py send         # отправка
python database.py            # посмотреть состояние базы по статусам
```

Локально `EGRESS_PROXY` оставляют пустым — с мака всё доступно напрямую.

## Запуск в Docker

```bash
docker compose run --rm digest collect
docker compose run --rm digest filter
docker compose run --rm digest send
docker compose run --rm digest send --quiet-if-empty   # вечерний вариант
```

Контейнер — не демон, а батч: поднимается на один прогон и умирает.

**Перед первым запуском** файлы `digest.db` и `digest.log` должны существовать,
иначе Docker создаст на их месте директории:

```bash
touch digest.db digest.log
```

## PROD — vlad-main

- **Путь:** `/opt/apps/svc-digest`
- **Расписание:** `/etc/cron.d/svc-digest`, от `root`, время сервера = MSK
  - `5 * * * *` — сбор каждый час в :05
  - `0 8 * * *` и `0 20 * * *` — отбор ИИ (только эти два захода тратят квоту)
  - `30 8 * * *` — 🌅 утренний дайджест
  - `30 20 * * *` — 🌆 вечерний дайджест (при пустой очереди молчит)
- **Логи:** `digest.log` (сам сервис) и `cron.log` (вывод cron) в папке проекта
- **Сеть:** `network_mode: host` + весь исходящий трафик через
  `EGRESS_PROXY=socks5://127.0.0.1:1080` (Xray, урок 5.09)

Проверить, что живой:

```bash
ssh admin@vlad-main 'tail -5 /opt/apps/svc-digest/digest.log'
```

## Настройка отбора

`interests.md` — что ИИ должен отбирать, обычным текстом. Файл примонтирован в
контейнер как bind-mount: правки применяются без пересборки образа.

## Структура

| Файл | Что делает |
|---|---|
| `digest.py` | точка входа, три команды: `collect`, `filter`, `send` |
| `collect.py` | тянет RSS (feedparser), окно 168 часов |
| `filter_ai.py` | отбор через OpenRouter, цепочка моделей с фолбэком |
| `database.py` | SQLite: `news` (new/pending/sent/rejected/expired), `collect_runs`, `filter_runs` |
| `render.py` | сборка текста дайджеста, по 5 новостей в сообщении, максимум 2 сообщения за раз |
| `telegram.py` | отправка от имени бота |
| `netcfg.py` | единая точка сетевой конфигурации (прокси) |
| `clock.py` | время: в базе UTC, человеку MSK |
| `bench_models.py` | замер моделей OpenRouter, вне рабочего контура |
| `interests.md` | config-as-code: критерии отбора |
| `СХЕМА.md` | Mermaid-карта конвейера |
