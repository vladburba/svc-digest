# Замер качества отбора

Здесь лежит способ отвечать числом на вопрос «стало ли лучше», когда меняются
критерии отбора, модель или её настройки. Без него любая правка оценивается
ощущением, а ощущение подводит: дважды за историю проекта казалось, что отбор
слишком широкий, а замер показывал ровно обратное.

## Как устроено

Выборка берётся из боевой базы: поровну того, что бот **отправил**, и того, что
**забраковал**. Человек размечает её вслепую — на странице не видно, что решил
бот, иначе измеряется не вкус человека, а его согласие с машиной. Потом оценки
сравниваются с решениями бота.

Считаются две ошибки, и они **не равнозначны**:

| ошибка | чем плоха |
|---|---|
| **зря прислал** | потратил внимание читателя, и тот это заметил |
| **зря выбросил** | читатель не увидел нужного и **даже не знает об этом** |

Вторая дороже и незаметнее — именно она оказывалась главной проблемой оба раза.

## Порядок работы

```bash
# 1. Собрать свежую выборку из боевой базы
python eval/collect_sample.py 2026-09-28 --since 2026-09-21

# 2. Сделать страницу для разметки (по 30 позиций за подход — больше утомляет)
python eval/make_page.py 1 30 2026-09-28-sample.json
python eval/make_page.py 31 60 2026-09-28-sample.json

# 3. Разметить, сохранить оценки в 2026-09-28-labels.json в том же формате,
#    что и у предыдущего набора

# 4. Посчитать и сравнить с прошлым замером
python eval/measure.py 2026-09-21 2026-09-28
```

Замер сети не требует и квоту OpenRouter не тратит: он сравнивает уже принятые
ботом решения с разметкой.

## Что уже измерено

**2026-09-21** — 30 позиций, 26 уверенных оценок:

```
согласие с ботом  54%
зря прислал        0
зря выбросил      12
```

Ноль лишних и двенадцать потерь — перекос целиком в сторону излишней строгости.
Все потерянные статьи прошли через отбор **до 21 сентября**, когда действовало
старое правило: не попал в пятёрку — отвергнут навсегда. В тот же день правило
заменено очередью: статья, признанная интересной, но не прошедшая по числу
мест, остаётся и участвует в следующем конкурсе.

Следующий замер (около 28 сентября) должен показать, сработала ли замена:
ожидаем заметного снижения «зря выбросил» при тех же нулевых «зря прислал».

Предыдущий замер в августе, ещё до этих файлов, дал 70% согласия и 16 потерь
на 53 оценки — тогда по его итогам переписали `interests.md`, и контрольный
прогон дал 10 попаданий из 10. Та выборка не сохранилась, потому что лежала во
временной папке; эта папка и появилась как ответ на ту потерю.

## Файлы

| файл | что это |
|---|---|
| `<дата>-sample.json` | выборка: заголовок, текст, ссылка и вердикт бота |
| `<дата>-labels.json` | ручная разметка: `+` оставить, `−` мимо, `0` не уверен |
| `collect_sample.py` | сбор свежей выборки из боевой базы |
| `make_page.py` | генератор страницы для разметки |
| `kartoteka.html` | шаблон страницы (данные подставляются генератором) |
| `measure.py` | подсчёт и сравнение замеров |

Оценки `0` в счёт не идут: учиться на том, в чём человек сам не уверен, значит
закреплять шум.
